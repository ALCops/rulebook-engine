# D56. Schema validation uses JsonSchema.Net directly, not Test-Json

- **Status:** Accepted
- **Date:** 2026-10-21

- **Decision:** the engine validates JSON against its schemas through JsonSchema.Net as shipped inside pwsh, with one function, `Test-RulebookSchema` of `Rulebook.Common`, used by Validate, the change-set reader and CI: each schema file is parsed once per session, evaluated with its own file location as base URI, and every distinct error comes back as `<text> at <JSON pointer>` (`at the root` for the document itself). The `Test-Json` cmdlet is no longer used for schema checks.
- **Rationale:** pwsh 7.6.7 (on `ubuntu-latest` since runner image 20261018) makes `Test-Json -SchemaFile` refuse a `$ref` to another file unless `-FetchExternalReference` is passed, so the three profile schemas, one-line `$ref`s to the sibling hub `ruleset.schema.json#/$defs/<profile>`, failed C1 on every ruleset file in every organization rulebook and in engine CI; and it writes no error record for a violation below the top level ([PowerShell#28218](https://github.com/PowerShell/PowerShell/issues/28218)), so a finding could not say what was wrong. The library `Test-Json` wraps resolves the sibling through the file base URI (a `SchemaRegistry.Fetch` on the evaluation options, routed through the same cache, so the hub is parsed once too) and returns every error with its JSON pointer on every pwsh 7.6 build ([#114](https://github.com/ALCops/rulebook-engine/issues/114), [#96](https://github.com/ALCops/rulebook-engine/issues/96)).
- **Rejected:** `Test-Json -FetchExternalReference` (a 7.6.7-only parameter that older builds refuse, and it leaves the nested errors silent); self-contained profile schemas (three copies of the hub that drift); `Test-Json -Schema <text>` with the hub inlined (the same drift, and the schema parsed on every call); bundling a JsonSchema.Net package in the repository (D9, and a second copy of an assembly pwsh already loads).
- **Consequences:** the engine depends on the JsonSchema.Net build inside pwsh: `Rulebook.Common` names the tested build (7.4.0, pwsh 7.6.3 to 7.6.7), a CI-only test pins it and an always-on test checks the API members the module uses, so another build fails a test, never Validate. The minimum stays pwsh 7.4, but an unpatched 7.4.0 (JsonSchema.Net 5.2.6) is unverified. The C1, C5, C10 and C14 messages and the change-set error lines end in ` at <pointer>`; the change-set hint line for a text without a named error is gone (the library always names one). A schema file that cannot be read or resolved throws out of `Test-Rulebook` (an engine defect, not rulebook input). No schema has an `$id`, which stays a rule: an absolute `$id` would replace the file base URI. The error texts are English because pwsh ships no satellite resources for the library; if a future pwsh ships them, pin `EvaluationOptions.Culture` to the invariant culture.
- **Affects:** [#96](https://github.com/ALCops/rulebook-engine/issues/96), [#114](https://github.com/ALCops/rulebook-engine/issues/114).
