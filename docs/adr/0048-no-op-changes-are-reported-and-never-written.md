# D48. No-op changes are reported and never written

- **Status:** Accepted
- **Date:** 2026-10-08

- **Decision:** a change set that changes no endpoint and would not change `overrides.json` is a no-op: the run reports it with a notice and a summary table, writes nothing, opens no pull request and succeeds without needing the token; a change that alters at least one endpoint is written and its table lists every matching endpoint, the unchanged ones marked `unchanged`; a change of the justification alone is written (every row `unchanged`, note `justification updated`); a `remove` whose selectors match no entry is a validation error that lists the entries the id has.
- **Rationale:** the issue asks that an override producing what the base already gives is reported and not written, and that setting an id to its analyzer default where the base deviates is written because the endpoint drops the id. Defining the no-op as "neither the file nor any endpoint changes" covers both and also keeps a deliberate justification edit, which changes the file the reviewer reads. A run that changed nothing is not a failure, so it exits 0; listing every matching endpoint in a partial change shows the reviewer the whole selection, not just the rows that moved. A remove that matches nothing is almost always a wrong selector, so naming the existing entries is the useful answer.
- **Rejected:** failing the run on a no-op (a red run for a correct form entry, and CI could not tell it from an error); writing the entry anyway (the file collects entries that do nothing, against the issue); removing every entry for the id when the selectors miss (deletes decisions the person did not select); treating a justification-only edit as a no-op (the justification could never be corrected through the form).
- **Consequences:** `Invoke-RulebookChangeSet` computes the rows from two in-memory input sets (the working tree and the candidate) and returns `NoOp` before regenerating; the action outputs `result=no-op` and `noop=true`; the token guard runs after the local plan, so a no-op and a validation error need no secret. Contract: [reference/change-mechanics.md](../reference/change-mechanics.md) section 4.
- **Affects:** WP09 ([#11](https://github.com/ALCops/rulebook-engine/issues/11)), WP15 (the change-set workflow shares the function and the rule).
