# D51. Test coverage is a report, not a gate

- **Status:** Accepted
- **Date:** 2026-10-10

- **Decision:** Pester writes JaCoCo line coverage for `modules/`, `actions/` and `scripts/` on every CI run and the job summary of the `test` job shows it per file; no percentage fails the build, tests are written where a behaviour is worth proving, and the accepted untested paths are listed in the testing reference page `docs/reference/testing.md`, which the WP12 testing-docs pull request adds.
- **Rationale:** a numeric gate pulls tests toward lines instead of behaviours, and the number is capped anyway: the descriptor extraction runs in a child pwsh the profiler does not see, and platform and defensive paths (Windows-only branches, a killed child process, an unreachable fallback) are not worth a test each. A visible per-file table on every run keeps coverage in view without making it a target.
- **Rejected:** the 80 percent gate (only in the design notes of [#14](https://github.com/ALCops/rulebook-engine/issues/14), never part of [D12](0012-testing-scope-for-v1-is-pester-unit-tests.md), which stays unchanged); a third-party reporter action (a new dependency and new permissions for what one pwsh step does); coverage over `tools/rulebook/` (those scripts are proven by `Test-Rulebook.ps1` in CI and by the template drift test, not by Pester).
- **Consequences:** the `test` job of `.github/workflows/ci.yml` runs Pester with `CodeCoverage` (profiler tracer, `UseBreakpoints` false), writes `coverage.xml` next to `testResults.xml`, runs `tools/ci/Write-TestSummary.ps1` with `if: always()` (the Pester and Coverage tables in the job summary, one error annotation per failed test) and uploads both files in the `testResults` artifact. Pester's `CoveragePercentTarget` is 0, so the target on its console line reads `/ 0%` and is always met (it only colours the line; it is not a gate). Pester's verbosity is `Normal`.
- **Affects:** WP12 ([#14](https://github.com/ALCops/rulebook-engine/issues/14)).
