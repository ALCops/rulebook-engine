# D49. The pages of the shipped levels live in the engine's docs

- **Status:** Accepted
- **Date:** 2026-10-09

- **Decision:** the pages of the shipped levels are generated by `tools/rulebook/Build-Template.ps1` (through `New-RulebookLevelDocs` of `Rulebook.Levels`) into `docs/levels/` of this repository and kept current by the Build-Template drift test; an organization's own levels get their pages from the WP14 site, built with the same model function `Get-RulebookLevelSummary`; neither `template/` nor the organization repository carries level pages, and Publish stays a gate that never commits (D42).
- **Rationale:** the shipped pages are the same for every organization and belong next to the matrix they explain, regenerated in the same pull request as a placement change. A `docs/` folder in the template is written once when an organization creates its repository and never touched again by the update (every `docs/**` file is organization-owned), so it would go stale with the first placement change. Publish stages committed files only and cannot write pages back. Computing the pages from repository inputs (settings, level files, chain, catalog) rather than from the matrix lets the same function describe any repository, custom levels included.
- **Rejected:** `template/docs/levels/` (stale after the first update, or a new update file class for Markdown pages); Publish rendering the pages (D42; the published site is the WP14 dashboard, which takes the model function instead); the update writing pages into the organization repository (noise in every update pull request, and pages for levels the organization may not use); pages computed from `matrix/resolved.json` (only the shipped levels have a matrix).
- **Consequences:** `Build-Template.ps1` writes one folder outside `template/` and takes `-LevelDocsDir`; the drift test regenerates the pages into a folder outside its template scratch copy and compares them with the committed `docs/levels/`, and a further test ties each page's counts to the V14 table in `docs/rulebook/README.md` section 4. The engine README lists `docs/levels/README.md`. WP14 consumes `Get-RulebookLevelSummary`. Open question 8 of [#12](https://github.com/ALCops/rulebook-engine/issues/12) is answered. The user docs in ALCops/rulebook link to the engine pages on `main` until WP13 pins `v1` ([#63](https://github.com/ALCops/rulebook-engine/issues/63)). Contract: [authoring-levels.md](../authoring-levels.md) section 4.
- **Affects:** WP10 ([#12](https://github.com/ALCops/rulebook-engine/issues/12)), WP13 (the deploy and the `v1` links), WP14 (the per-organization pages on the site).
