# D21. No target dimension: one ladder per rule, both Microsoft cops at their native severity

- **Status:** Partly superseded by D25 and D28 (2026-10-01)
- **Date:** 2026-10-01

- **Partly superseded** by D25 and D28 (2026-10-01): 12 files per set, lowercase slug names. The removal of the target dimension stands.
- **Decision:** the `target` axis (`pte`, `appsource`, `all`) is removed. Every rule has one ladder that applies to every AL project. PerTenantExtensionCop and AppSourceCop rules with an Error default are `Error` at every level, because each is the deployment blocker of one kind of extension and Rulebook does not know which kind a project is. Family `marketplace` (the AppSourceCop checks that need `AppSourceCop.json` or marketplace manifest fields) and the baseline-missing diagnostics AS0003 and AS0091 are `None` at Essential and native from Recommended. Family `pte-only` is native at every level. The adjustments of Microsoft's own AppSource validation ruleset (AS0075 and AS0099 hidden, AS0089 lowered to Warning) apply to every project. An endpoint is `rulesets/L<n>.<stage>.ruleset.json`; with `L0` that is 13 files per set. A project that hits a contradiction between the two cops (PTE0001 and PTE0002 against AS0084 and AS0013 on id ranges, the marketplace manifest checks) opts out itself: by disabling a cop in `al.codeAnalyzers`, by `suppressWarnings` in `app.json` (works because of D22), or by a rule in its project ruleset file. The template documents the three routes with ready-made lists.
- **Rationale:** all analyzers are already assumed to be enabled in every project. The target only existed to subtract one cop's rules for the other kind of project, which pre-decides something the project can decide better and cheaper, and it tripled every file set. Following the analyzer author's severity for every rule is the simplest story to document and the one closest to a compile without any ruleset.
- **Rejected:** keeping only the former `all` ladder (its twin policy put the PerTenantExtensionCop side at `None`, so a project that disables AppSourceCop would lose 17 checks silently); keeping the three targets (what the interview asked to remove); marketplace checks native from Essential (AS0054 and AS0051 fire in every project without `AppSourceCop.json`, which makes Essential unusable without configuration).
- **Consequences:** D5's dimensions, the target halves of D16 and D17 and open decision O5 are superseded or moot. Matrix columns `PTE` and `AppSource`, target rules T-1 to T-5, override selector `targets`, the ChangeRule input `targets` and the settings array `targets` disappear. `docs/rulebook/decisions.md` records the new placements as DR-018 to DR-021. Twins become an organization setting (D23).
- **Affects:** WP01 to WP13; `docs/rulebook/` and `tools/rulebook/` in full.
