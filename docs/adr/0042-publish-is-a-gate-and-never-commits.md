# D42. Publish is a gate and never commits

- **Status:** Accepted
- **Date:** 2026-10-06

- **Decision:** the Publish workflow validates the repository and refuses to deploy when the committed `rulesets/` differ from what the inputs generate (C12), so the published endpoints only ever change through a pull request that commits the regenerated files; Publish holds no write token and never pushes a commit.
- **Rationale:** the endpoints are what every AL project compiles against, so a change to them should be reviewed like code: the Validate workflow prints the effective diff on the pull request and a reviewer sees exactly what consumers will get. A Publish that regenerates and commits on `main` would publish a change nobody reviewed, would need `contents: write` (or `GHTOKENWORKFLOW`) on a workflow that runs on every push, and would fight branch protection and the update and change workflows that already open pull requests (D11, D32). Stale endpoints on `main` only happen when someone bypasses the pull request; failing loudly with the fix is the right answer, and the site keeps serving the last good publish.
- **Rejected:** regenerate and commit when anything changed (the WP05 issue text: unreviewed endpoint changes, a write token on every push, a commit loop with the push trigger, and the rule "never edit `rulesets/` by hand" becomes "the robot edits it"); regenerate into the staging folder without committing (what is published would then differ from what is committed, which breaks "what you see is what the compiler loads", D18, and the reachability check would have nothing to compare with); publish anyway with a warning (consumers would get endpoints that disagree with the repository).
- **Consequences:** `actions/Publish` stages the committed files and refuses a missing or stale endpoint itself (`New-RulebookPublishStage`), in addition to the Validate step that runs first in `Publish.yaml`. The workflow token gets `contents: read`, `pages: write` and `id-token: write` only. The fix for a failing Publish is always a pull request: regenerate with `Update-RulebookEndpoints` (or let the Validate workflow name the stale files) and merge. ARCHITECTURE.md sections 3, 4 and 7.2 no longer say that Publish regenerates; the writing workflows (Update, Scan, ChangeRule, Apply) still regenerate inside their pull requests.
- **Affects:** WP05 ([#7](https://github.com/ALCops/rulebook-engine/issues/7)), WP07, WP08, WP09, WP15.
