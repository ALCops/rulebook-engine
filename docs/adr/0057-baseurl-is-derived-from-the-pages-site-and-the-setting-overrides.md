# D57. baseUrl is derived from the Pages site, and the setting overrides it

- **Status:** Accepted
- **Date:** 2026-10-21

- **Decision:** when `baseUrl` is empty (the action input and the setting), the Publish action with `deploy` true takes `html_url` of `GET /repos/{owner}/{repo}/pages`, without its trailing slash, as the base URL for the skeletons, `rulebook.json`, the site build and the manifest; a set `baseUrl` overrides it and is validated as before. A dry run (`deploy` false) makes no API call and keeps the `baseUrl-empty` failure with the proposal. A private site (`public: false` in the same answer) ends the run green with a warning, the output `private` and no reachability check. `baseUrl` stays required in the settings schema and the template keeps shipping `""`.
- **Rationale:** the preflight already reads the Pages site on every deploy, and `html_url` exists as soon as the site is created (Source set to GitHub Actions), before the first deploy, for public sites, private sites and custom domains alike, so the address GitHub serves is known without the organization typing it. Typing it was the one manual settings step of the setup, it went stale after a custom domain or a rename, and it hid the private host of an Enterprise Cloud organization with Enterprise Managed Users: with `baseUrl` set to `https://<owner>.github.io/<repo>` the deploy succeeded and the check failed after 660 s on every URL with a redirect, and with `baseUrl` empty the run stopped before the preflight that carries the address ([#134](https://github.com/ALCops/rulebook-engine/issues/134)). A private site cannot serve the AL compiler (anonymous requests answer `302` to a sign-in and the compiler follows no redirect), but the dashboard works for signed-in colleagues, so the run should deploy it and say plainly that the endpoints are not reachable, instead of failing a check that can never pass.
- **Rejected:** keeping `baseUrl` mandatory (the manual step and the stale value stay, and an EMU organization gets a red run for a site that works as a dashboard); deriving the address from the repository name (`https://<owner>.github.io/<repo>`) without asking GitHub (wrong for a custom domain and for a private site); writing the derived value back into the settings (Publish never commits, D42); dropping `baseUrl` from the schema's `required` (organization settings that carry it stay valid either way, and the template's `""` documents the key); failing the run on a private site (nothing the organization can change on an EMU account, and the deployed dashboard is useful); running the reachability check with a signed-in token on a private site (the compiler cannot, so a passing check would prove nothing).
- **Consequences:** `Resolve-RulebookBaseUrl` gains `-AllowEmpty`; `Get-PagesPreflightResult` returns `HtmlUrl` and `Private`, and `Warning` becomes an array of up to two texts (the private site, and a set `baseUrl` that differs from `html_url`). The Publish action declares the output `private` and its check step reads it. The failure kinds `baseUrl-empty` (a dry run, or a Pages answer without `html_url`) and `baseUrl-invalid` keep their meaning. The user docs make `baseUrl` optional and document private sites; the endpoints of an EMU organization need another target ([#56](https://github.com/ALCops/rulebook-engine/issues/56)).
- **Affects:** [#134](https://github.com/ALCops/rulebook-engine/issues/134), [#56](https://github.com/ALCops/rulebook-engine/issues/56), D42.
