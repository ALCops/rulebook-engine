# D41. Quarantine wins over a stage entry for an id no level file mentions

- **Status:** Accepted
- **Date:** 2026-10-05

- **Decision:** the level result of an id in an endpoint is the level chain where a file on the chain mentions the id, else `None` when the stage's `quarantine.<stage>.json` lists the id, else the analyzer default; a stage entry applies only where that level result is not `None`, so the precedence stays override, twins, stage delta, level chain, quarantine, analyzer default, with quarantine folded into the level result the stage condition (S-4) looks at.
- **Rationale:** quarantine means "not adopted yet" under the organization's own quarantine policy (D14). A shipped `stages/ci.json` or `stages/vnext.json` entry can arrive with a template update before any level file adopts the id; it must not switch on an id the organization has not reviewed. Adoption is a level file mentioning the id, after which the chain wins and the scan's housekeeping removes the quarantine entry (D27); the stage entry then applies as usual. An organization that wants new ids active on vNext right away leaves vNext out of its quarantine policy. The rule needs no new concept: S-4 already says a stage never activates a rule, and quarantine `None` is now part of the result S-4 inspects.
- **Rejected:** stage wins (the reading WP02 left in the pseudocode: a template update PR can activate a quarantined id, and the organization could block that only with one override per id and stage); an error instead of a warning for the dead stage entry (the stage file is a system file the organization cannot edit, so an error would block every update PR until a level file adopts the id).
- **Consequences:** [rulebook/composition.md](../rulebook/composition.md) section 3 writes the precedence in two steps (level result, then effective action); [ARCHITECTURE.md](../ARCHITECTURE.md) section 5.1 rows 3 and 5 say the same. Validation gains the warning check C15: a stage entry on an id the same stage quarantines and no chain file of any published level mentions ("dead while quarantined"). `Get-EffectiveAction` in `Rulebook.Generate` implements it, the fixture `tests/fixtures/repos/quarantined-stage-entry` and the precedence tests prove it, and the dashboard shows `quarantine` as the provenance of such a cell (WP14). D27 keeps its text and gets a note pointing here.
- **Affects:** WP03 ([#5](https://github.com/ALCops/rulebook-engine/issues/5)), WP04, WP08, WP14; closes [#42](https://github.com/ALCops/rulebook-engine/issues/42).
