# D58. alcops.dev is canonical, the site explains itself, the organization repository keeps its own text

- **Status:** Accepted
- **Date:** 2026-10-28

- **Decision:** the user documentation of Rulebook gets one canonical home, a Rulebook section on alcops.dev that serves the latest release only at one path per template page (`https://alcops.dev/docs/rulebook/<page>/`); the organization's published site explains itself in context and deep-links there; the organization repository's `docs/` keeps a README and the organization's own text; the engine's `docs/` stays contributor documentation. Until alcops.dev serves the pages, `template/docs/` ships them in full and every link the engine writes keeps targeting them on GitHub.
- **The content map:**

  | Place | Carries | Audience |
  |---|---|---|
  | alcops.dev, section `docs/rulebook/` | Every page of `template/docs/` (getting started, PTE or AppSource, hosting, the AL project, AL-Go, Azure DevOps, VS Code, levels, changing a rule, overrides, quarantine, updating, the write token, migration, FAQ, versioning, the dashboard), the generated pages of the shipped levels (engine `docs/levels/`, D49), reference material and a glossary. The latest release only (below). | The maintainer who sets up or runs a rulebook; the developer looking something up |
  | The organization's site | A "How this works" page, a one-line lead under every page title, the legend tooltips, the setup page, and a deep link to alcops.dev for every concept ([#143](https://github.com/ALCops/rulebook-engine/issues/143)). Nothing that goes stale with an engine release; no site file names a documentation URL, the targets come from `rulebook.json`. | The developers and maintainers of that organization, in context |
  | The organization repository, `docs/` | A `README.md` that points to alcops.dev and to the site, and the organization's own text: which level is the house standard, who approves a change, how an exception is requested. Customizable (D50). The repository's root `README.md` stays the organization's front page (org-owned). | That organization |
  | The engine, `docs/` | Contributor documentation: architecture, decisions, reference, design, the level matrix, and the source of the generated level pages (D49). Unchanged. | Engine contributors |

- **Versions:** alcops.dev serves one version, the latest release (the template's `main`, D53): no version switch. Every Rulebook page on alcops.dev carries one note that names the release it documents and links the same page on the template's `preview` branch (`https://github.com/ALCops/rulebook/blob/preview/docs/<page>.md`) for what comes next; there are no hand-written per-paragraph preview notes. An organization that follows `preview` (the canary) or pins a release tag keeps reading the pages of its own ref on GitHub, through the mapping below.
- **The anchor scheme:** one path per template page, lowercase with a trailing slash, as alcops.dev's Hugo site (Docsy, pretty URLs) already serves `content/docs/getting-started/quick-start.md` at `/docs/getting-started/quick-start/` and the analyzers at `/docs/analyzers/<cop>/<id>/`: `template/docs/README.md` becomes the section index `https://alcops.dev/docs/rulebook/`, and `template/docs/<page>.md` becomes `https://alcops.dev/docs/rulebook/<page>/` with the file name kept as the slug (`levels.md` to `levels/`, `pte-or-appsource.md` to `pte-or-appsource/`, `changing-a-rule.md` to `changing-a-rule/`). A link to a section keeps its fragment: Hugo's default heading ids (`autoHeadingIDType` `github`) are GitHub's, so `dashboard.md#4-what-is-public` becomes `dashboard/#4-what-is-public`. The generated level pages go under `https://alcops.dev/docs/rulebook/levels/<level>/` (the levels page is the parent). Renaming a template page renames its alcops.dev path, so a rename keeps a redirect (Hugo `aliases`).
- **The `docs` map and the repointing:** the engine writes a `docs` map into `rulebook.json` (WP16, [#138](https://github.com/ALCops/rulebook-engine/issues/138)) with the keys `home` (`https://alcops.dev`, the only entry that is no documentation page), `dashboard`, `levels`, `overrides`, `quarantine`, `twins` (`pte-or-appsource.md`), `changingARule` and `alProject`, built through `Get-RulebookDocsUrl` of `Rulebook.Common` next to the existing `docsUrl` and `alProjectDocsUrl`, which equal `dashboard` and `alProject`. Until alcops.dev serves the pages, `Get-RulebookDocsUrl` keeps mapping the engine ref to the template ref that holds the page on GitHub, as it does today (D53). Once it serves them, the repointing is an engine-only change in that one function: the engine ref `v<n>` (and a commit sha, which maps to the release today) returns the alcops.dev path of the page; `main` and any other branch keep the template's `preview` on GitHub and a release tag keeps the same tag there, because alcops.dev serves only the latest release. Every consumer follows: the `docs` map, `docsUrl`, `alProjectDocsUrl` and the links the actions print. The site never changes; it renders the targets it finds in the data file.
- **What `template/docs/` ships:** every page in full until alcops.dev serves them, so an organization's documentation is never a set of links to pages that do not exist. After the move the template ships `docs/README.md` only: the pointers to alcops.dev and to the site, and headings for the organization's own text. The pages the template no longer ships follow the update's rule for removed template files ([ARCHITECTURE.md](../ARCHITECTURE.md#73-update-rulebook-system-files-r5) section 7.3): an organization's copy stays, with a note in the update pull request, until it lists the page in `unusedRulebookFiles`, which removes it; a copy the organization edited is its own text from then on. `docs/**` stays in the customizable class of D50.
- **Rationale:** decided in the WP16 planning interview of 2026-10-24 ([#136](https://github.com/ALCops/rulebook-engine/issues/136)) and settled in the WP16 execution interview of 2026-10-28 ([#142](https://github.com/ALCops/rulebook-engine/issues/142)). Three places carry documentation today and none is canonical: the user pages ship into every organization repository and are read through GitHub's rendering of the template (the site's Help link), alcops.dev documents the analyzers only, and the site explains nothing. One home per page means one place to fix it; alcops.dev is where an AL developer already reads about ALCops rules, so the Rulebook pages belong next to them, and a search engine finds one copy instead of one per organization. The site is the place a developer stands when the question comes up, so it carries the short in-context text, and only text that holds for every engine release, because an organization's site files are customizable (D35) and lag behind. What only an organization knows (its house standard, its approvers) can never be canonical anywhere else, so its repository keeps it. One version on alcops.dev keeps the site simple and matches the support policy: only the latest release is supported (D53); the few readers on `preview` or on a pinned tag get exact text from the template on GitHub. Routing every link through `Get-RulebookDocsUrl` and the data file makes the move a one-function change on a release instead of an update of every organization's site.
- **Rejected:** keeping the GitHub rendering of the template as the canonical home (no search, no navigation, the template repository's file list as the reader's first sight, and a different reading place per ref); a version switch on alcops.dev (a second build and menu for releases nobody is supported on, D53); per-paragraph preview notes written by hand (they go stale and nobody checks them; the one generated note links the exact preview text instead); serving the pages from each organization's own site (the site would carry text that goes stale with every engine release, and D35 lets organizations keep old site files); dropping `template/docs/` right away (organizations would get links to pages alcops.dev does not serve yet); site files naming alcops.dev URLs (a literal no engine release can repoint; the Deploy test forbids it).
- **Consequences:** the mechanics of getting the pages onto alcops.dev stay in [#105](https://github.com/ALCops/rulebook-engine/issues/105); this record states the requirement they must meet: the release refreshes the alcops.dev Rulebook section from the template's `main` without hand work, keeps every path of the scheme above stable, turns the relative links between pages and to `images/` into working links on alcops.dev, and writes the version note on every page. Until then nothing moves and `Get-RulebookDocsUrl` targets GitHub. The repointing is a later engine pull request, after #105, with a release line; the switch to the README-only `template/docs/` is another, with a release line that tells organizations to list the old pages in `unusedRulebookFiles` (moving no file between classes, so no deprecation under [releasing.md](../releasing.md) section 4). [ARCHITECTURE.md](../ARCHITECTURE.md) section 3 and `template/docs/README.md` follow the content map. The list of alcops.dev pages to create, with their template source pages, is a checklist on #142. #136 reserved D58 for the theme decision of its spike ([#137](https://github.com/ALCops/rulebook-engine/issues/137)); that decision becomes D59 because this record merged first.
- **Affects:** [#142](https://github.com/ALCops/rulebook-engine/issues/142), [#105](https://github.com/ALCops/rulebook-engine/issues/105), WP16 ([#136](https://github.com/ALCops/rulebook-engine/issues/136), the `docs` map of [#138](https://github.com/ALCops/rulebook-engine/issues/138), the help of [#143](https://github.com/ALCops/rulebook-engine/issues/143)), D49, D50, D53.
