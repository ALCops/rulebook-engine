# D22. Sparse endpoints: an id at its analyzer default is not listed

- **Status:** Partly superseded by D25 and D27 (2026-10-01)
- **Date:** 2026-10-01

- **Partly superseded** by D25 and D27 (2026-10-01): the `L0` sentence no longer applies and the files in `base/` are deltas, not complete records; the matrix in the engine is the readable record.
- **Decision:** a generated endpoint lists only the ids whose effective action differs from the analyzer default. The default of an id is its descriptor severity when `isEnabledByDefault` is true and `None` otherwise. `base/` files stay complete, every id with action and justification, because they are the readable record and are never fetched. The generator reads the defaults from `catalog/diagnostics.json` (D24).
- **Rationale:** the compiler merges `suppressWarnings` from `app.json` with the ruleset strictest-wins, after the ruleset is loaded (`CommandLineParser.cs` lines 543 to 558, `CompilationOptions.MergeDiagnosticOptions`, `VsCodeWorkspace.cs` line 400), and `None` is never stricter than anything. So `suppressWarnings` can only switch off an id the ruleset does not mention. With D21 the rules a project most wants to switch off (the other cop's blockers) sit at their native severity, which is exactly what a sparse endpoint leaves unmentioned. The fetched file shrinks to the deviations, and when an endpoint is unreachable (AL1033) the compiler's fallback to analyzer defaults is now close to what Rulebook intended instead of the opposite of it.
- **Rejected:** every id explicit (D18; blocks `suppressWarnings` for everything and makes the fallback on AL1033 maximally wrong); omitting only the known contradicting ids (a special case that needs a hand-maintained list).
- **Consequences:** the "every id explicit" half of D18 and the validation rule "every catalog id appears in every endpoint" of D19 are superseded. New validation: no listed entry equals the catalog default; the regeneration check covers completeness. Analyzer default changes alter the effective ruleset silently unless tracked, hence D24. `L0` lists every enabled-by-default id at `None` and omits disabled ones. Quarantine entries are always written because `None` differs from an enabled default.
- **Affects:** WP02, WP03, WP04, WP06, WP08, WP11, WP12.
