# D19. Organization overrides and quarantine are generator inputs

- **Status:** Partly superseded by D27 (2026-10-01)
- **Date:** 2026-09-29

- **Partly superseded** by D27 (2026-10-01): the base input is the level chain plus the stage deltas; precedence is override, twins, stage delta, level chain, quarantine, analyzer default.
- **Decision:** an organization repository holds three inputs and one output. Inputs: `base/<endpoint>.ruleset.json` (system files generated in the engine from the matrix, entries carry a `justification`), `overrides.json` (org-owned; entries `{ id, action, levels, targets, stages, justification }` with `*` wildcards, one file, mirroring the ChangeRule form) and `quarantine.<stage>.json` (org-owned, written by the daily scan). Output: `rulesets/<endpoint>.ruleset.json`, regenerated by the Validate and Publish actions and committed. Precedence per id: override, then base, then quarantine; quarantine only affects ids the base does not mention. Endpoint entries carry `id` and `action` only; the justification stays in the matrix and in `base/`.
- **Rationale:** with no include chain there is no file position where an override or a quarantine entry can win by merge semantics; they have to be folded in at generation time. One overrides file with scope selectors is one thing to review and maps one to one onto the ChangeRule inputs. Committing the output keeps the effective ruleset reviewable in every pull request. Dropping justifications from the endpoints keeps the one fetched file at roughly a quarter of its size; the reason is one hop away in `base/`.
- **Rejected:** editing the flat endpoints in place (update PRs would three-way merge 37 files); overrides only in the AL project skeleton (no organization-wide exceptions); one overrides file per endpoint (a change to all levels touches many files); generating on publish without committing (reviewers could not see the effective diff).
- **Consequences:** the update workflow overwrites `base/`, never touches `overrides.json` or the quarantine files, and regenerates `rulesets/`. The scan writes quarantine entries and regenerates. ChangeRule writes an override entry and regenerates. Housekeeping removes a quarantine entry once `base/` mentions the id. Validation adds a regeneration check: the committed endpoint must equal the regenerated one. Closes O1 (overrides live in `overrides.json`) and O2 (stages are columns of the matrix, D17; no overlay can conflict).
- **Affects:** WP02, WP03, WP04, WP07, WP08, WP09.
