# D32. Dashboard writes go through a prefilled GitHub issue form applied by a workflow

- **Status:** Accepted
- **Date:** 2026-10-03

- **Decision:** the dashboard never writes to the repository. Its cart opens `issues/new?template=rulebook-change.yml&changes=<json>` in the organization repository, prefilled through issue-form query parameters; the maintainer submits with their own GitHub session; a workflow on `issues: [opened, edited]` filtered by the `rulebook-change` label validates and applies the change set through the engine. v1 operations: set or remove an override, release an id from quarantine. Levels and stages configuration and org-owned level and stage files are not editable from the dashboard in v1.
- **Rationale:** the owner's constraints are GitHub only and no custom login. A static page cannot hold a credential, and GitHub's OAuth and device-flow endpoints send no CORS headers, so every "sign in with GitHub" needs a proxy. The user's existing github.com session on a GitHub-owned page is the only credential source left that needs neither a token in the browser nor a server. Issue forms give a reviewable, typed hand-over, and the parsing fragility D11 feared is bounded: one `render: json` field, one fenced block.
- **Rejected:** a fine-grained PAT pasted into the page (token creation is the hurdle the dashboard removes; a browser profile would hold write access); OAuth through a Cloudflare Worker or Azure Function (breaks GitHub only, one more thing per organization to operate); a hosted application with GitHub login such as Azure Static Web Apps (best UX, but a non-GitHub component or a central ALCops service); a VS Code web extension through github.dev (GitHub only, no infrastructure, but the user must open the repository in an editor; kept as a later client of the same module); copy-and-paste into GitHub's editor (no automation; remains the fallback when a cart exceeds the URL limit); a custom username and password on the site (rejected outright as a security problem).
- **Consequences:** `Rulebook.Edit.psm1` gains `Invoke-RulebookChangeSet` and `Remove-RulebookQuarantine`; ChangeRule (WP09) becomes a one-item client of it. A change-set schema is published with the other schemas. The URL length GitHub accepts is unknown and decides the cart size (spike WP01 (g)). D11 is partly superseded.
- **Affects:** WP01, WP09, WP14, WP15.
