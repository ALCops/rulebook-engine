# D43. rulebook.json is published from WP06 with the levels and stages

- **Status:** Accepted
- **Date:** 2026-10-06

- **Decision:** the Publish action stages `<baseUrl>/rulebook.json`, the minimal form of the dashboard data contract (dashboard.md section 5): `generatedAt`, `repository` (when the action knows it), `baseUrl`, `levels[]` (`name`, `slug`, `basedOn` as a slug when set, `description`) and `stages[]` (`name`, `slug`, `description`), without `rules`, `overrides` or `quarantine`; WP14 extends the same file.
- **Rationale:** the init script `scripts/Get-RulebookSkeletons.ps1` (WP06) has to know which levels and stages a site publishes before it downloads anything, so it can refuse an unknown level and name the published ones, and so it writes one file per stage of this organization rather than of the shipped set. The dashboard needs exactly this list as the head of its data file anyway (D31), so publishing it now under its final name costs one small file and gives every later reader one stable, machine-readable source. `basedOn` is written as the slug because the slug is the identity in every file, URL and key (D28).
- **Rejected:** parsing `index.html` (the issue's first idea: the page is presentation, its markup changes with WP14 when the Hugo site replaces it, and a script that scrapes HTML breaks silently); a separate `levels.json` (a second file with the same content as the head of `rulebook.json`, which WP14 would then have to keep in step or deprecate); publishing `.github/Rulebook-Settings.json` itself (it holds the template URL, the quarantine policy and the commit options, which consumers do not need, and its shape is the settings schema, not a published contract; Publish publishes nothing from `.github/`).
- **Consequences:** `New-RulebookPublishStage` writes `rulebook.json` with kind `manifest` in the staging manifest (order: endpoints, skeletons, manifest, index), the reachability check requests it like every other URL (26 URLs in the shipped set), and the engine CI asserts its fields. Fields are only ever added: readers, the init script first, ignore keys they do not know. `generatedAt` changes on every publish, so the file is not byte-stable between runs; nothing compares it across runs. `repository` comes from `GITHUB_REPOSITORY` today; WP14 may move it to a setting when a target other than Pages needs it.
- **Affects:** WP06 ([#8](https://github.com/ALCops/rulebook-engine/issues/8)), WP14 ([#16](https://github.com/ALCops/rulebook-engine/issues/16)).
