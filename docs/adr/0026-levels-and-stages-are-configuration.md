# D26. Levels and stages are configuration

- **Status:** Accepted
- **Date:** 2026-10-01

- **Decision:** `Rulebook-Settings.json` holds `levels` and `stages` as ordered arrays of `{ name, description }`; a level may carry `basedOn` (D27). The template ships Essential, Recommended, Strict and Complete, and `default`, `CI` and `vNext`. An organization adds, removes or aliases entries. `default` must be present; it is the stage every consumer without its own stage uses. Array order is presentation order (index page, docs, dropdowns), nothing more. There is no check that a level is at least as strict as the level it is based on: a higher level may set a rule to `None` where the lower level says `Warning`. The engine keeps invariant I2 (cumulative) for the shipped four as an authoring rule, not as a validation of organization repositories.
- **Rationale:** requirement R8 asked for extensible levels. With delta files a custom level or stage is one file plus one settings entry, so the tooling cost that D20 avoided no longer exists. Making the set configurable without making the content order-dependent keeps one model: a level is a named starting point plus changes. A team that wants a laxer rule at a higher level is making a decision, not an error; the effective diff report is where a reviewer sees it.
- **Rejected:** fixed four levels with editable names only (D20; a fifth level or a different split was impossible without a template change); an enforced monotonic ladder (makes a scoped override `levels: ["recommended"]` an error and tells teams what their levels may mean); unordered profiles (loses the ladder as a story in the docs).
- **Consequences:** every file name, URL, selector and key is derived from the settings (D28). The matrix, the ladders and the DR records in `docs/rulebook/` describe only the shipped content. The validation of an organization repository checks the settings shape, the file set and the slug rules (C5, C6, C11) and nothing about strictness between levels. `quarantine.stages` and `prereleaseStages` hold stage slugs from `settings.stages`. Closes WP09's open question on dropdowns together with D30. Supersedes D20; refines D4 and D15; partly supersedes D14 and D17.
- **Affects:** WP02, WP03, WP04, WP05, WP06, WP07, WP08, WP09, WP10, WP11.
