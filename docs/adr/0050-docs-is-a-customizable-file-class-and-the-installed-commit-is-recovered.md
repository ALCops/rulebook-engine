# D50. `docs/**` is customizable too, and an unrecorded installed template commit is recovered from the root commit's tree

- **Status:** Accepted
- **Date:** 2026-10-09

- **Decision:** the shipped `docs/**` joins the customizable class of D35 with its own key `docs.updateMode` (`skip`, the default, or `overwrite`), and when `templateSha` is empty the update takes the tree of the organization repository's root commit, finds the newest commit on the template branch with that tree (the commit "Use this template" copied) and uses it as the installed version; no match keeps D35's skip behaviour and says so in the pull request.
- **Rationale:** the organization documentation in `docs/` is hand-written onboarding text that organizations adapt (their own hosting, their own consumers), the same situation as the site: an unedited page should follow the template, an edited one must survive. `README.md` is the organization's front page and stays org-owned. Separate keys because the site and the documentation have different owners in an organization. "Use this template" produces one root commit whose tree equals the tree of the template commit it copied (verified on 2026-10-09 on three repositories created from microsoft/AL-Go-PTE: MyPTE, AL-Go-LinterCop, adventofcode2023), so the first update of every repository becomes a real three-way comparison without any instruction to the organization; without it, every page or site file that differs from the new template would be skipped on the first update.
- **Rejected:** `docs/**` org-owned (pages go stale after the first template change, D49's reasoning); the overwrite class for `docs/**` (an organization's adaptations lost on every update); one shared key for `site/` and `docs/` (different owners); linking the engine docs instead of shipping pages (no local copy to adapt); GraphQL `history(last: 1)` to find the root commit (a second API shape and mock surface next to REST); recording `templateSha` when the repository is created (no workflow runs on "Use this template"); a content hash over the working tree instead of the git tree (every later edit breaks it).
- **Consequences:** `docs/**` is managed: a page the organization deletes without listing it in `unusedRulebookFiles` is added again by the next update (the user documentation says so). The skipped section of the update pull request is "Skipped: local changes" and names `site.updateMode` and/or `docs.updateMode`. The recovery reads the root tree from the checkout, which needs full history (`fetch-depth: 0` on the shipped `UpdateRulebookSystemFiles.yaml`; until an organization has that workflow version the REST walk of its own repository serves, at most 1000 commits), and the template branch's commits through REST with the token that read the template (at most 1000). The recovered commit is only the old side of the comparison; `templateSha` still records the new head. D35's "every differing site file counts as local when `templateSha` is empty" holds only when the root tree is not found. WP13 ships `docs/` from ALCops/rulebook, not from `template/`. Contract: [update-mechanics.md](../reference/update-mechanics.md) sections 1, 3 and 6.
