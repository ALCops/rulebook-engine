# D54. The site renders one page per stage, and the engine exports the fallback action

- **Status:** Accepted; "/" is a landing page since 2026-10-28 ([#139](https://github.com/ALCops/rulebook-engine/issues/139)), the grid of the first stage at stages/<slug>/
- **Date:** 2026-10-17

- **Decision:** the dashboard site renders one static page per stage (`/` is the grid of the first stage, `stages/<slug>/` every stage with its stage summary), one per level and one per rule, and the engine exports, for every override and quarantine cell, the action the cell would have without that input, so the cart shows the before and after of a change without any precedence logic in the browser.
- **The shape:**
  - *Pages.* `/` and `stages/<slug>/` render the same matrix partial: one row per rule, one column per level, the cells of that stage. The stage links are plain links; `/` is the first stage, rendered again rather than as a Hugo alias, because an alias is a meta-refresh page that shows nothing without JavaScript and would not equal the staged body the reachability check compares. Every stage page also carries the stage summary of [#84](https://github.com/ALCops/rulebook-engine/issues/84) (`Get-RulebookStageSummary`); `levels/<slug>/` renders the level model (`Get-RulebookLevelSummary`, so an organization's own levels get a page, D49) and `rules/<id>/` the twelve cells of one rule with the same cell partial. Hugo lowercases page paths (`rules/lc0089i/`); a cell keeps the real id in `data-id`. All pages come from one data file, `site/data/rulebook.json` (docs/dashboard.md section 5), read as `hugo.Data.rulebook`.
  - *State in the browser.* The filters (analyzer, action, deciding input, text) live in the URL hash, so a stage link keeps them; the cart lives in `localStorage` under `rulebook-cart:<repository>`. Without JavaScript the grids and every page work; the filters, the popover and the cart stay hidden.
  - *Fallback.* `Get-RulebookSiteModel` writes `fallback` and `fallbackSource` on override cells (with `override`, the index of the winning entry) and on quarantine cells, computed by `Get-EffectiveAction` with that one input left out ([dashboard.md](../dashboard.md) section 5). The cart takes, for a `set`, the chosen action; for a `remove`, the fallback of every cell whose `override` is the entry's index; for a `release`, the fallback of the quarantine cells of the stages. The pure functions are `template/site/assets/js/cart-core.mjs`, tested with `node --test` in the `publish-action` CI job, without npm.
  - *Build.* The Publish action installs the pinned Hugo (`HUGO_VERSION` 0.167.0, the `.deb` SHA256 pinned next to it in `actions/Publish/action.yaml`) when `site.enabled` is true, and builds `site/` into the staging folder after the endpoints, skeletons, `rulebook.json` and `catalog/diagnostics.json` are staged, with `--noBuildLock` and without `--cleanDestinationDir`; Hugo's `index.html` replaces the plain one. A missing Hugo or a failed build fails the run with failure `site`, and the previous deployment stays live; a target that cannot serve HTML or a missing `site/hugo.yaml` is a warning and keeps the plain `index.html`. Both data files are staged on every run; `site.enabled` decides only the HTML. The reachability check requests every stage and level page and the first rule page as kind `page`, and the catalog as kind `catalog`.
- **Rationale:** decided in the WP14 planning interview of 2026-10-12 and 2026-10-17 ([#16](https://github.com/ALCops/rulebook-engine/issues/16)).
  - *One page per stage.* One page with every stage rendered and two hidden triples the HTML of the largest page (about 0.6 MB per stage at 628 rules and four levels, measured with the shipped template) and shows nothing useful without JavaScript; a page per stage stays at the size of one grid and is complete without scripts.
  - *The fallback from the engine.* The precedence (override, twins, stage, level, quarantine, default, with the quarantine and stage rules of ARCHITECTURE section 5.1) lives in `Rulebook.Generate`. A copy in JavaScript would drift from it the first time the generator changes; the exported fallback is the generator's own answer, and the apply workflow of WP15 can compare its before and after with it.
  - *Pinned hash.* Pinning the SHA256 in the action instead of reading the release's checksums file at run time keeps the check independent of the same download source it checks.
- **Rejected:** all stages on one page switched by JavaScript (size, no-JS view); a Hugo alias for `/` (meta refresh, body differs from the staged file); before and after computed in the browser from the level, stage and override data (a second resolver); a Playwright or browser test layer (D12 keeps v1 at unit tests; the pure cart functions carry the logic and run under `node --test`); npm, a framework or fingerprinted assets (an organization adapts the site by editing plain files, and the published asset paths stay fixed); all 628 rule pages in the reachability check (the stage, level and first rule page show the site is served; 628 more requests add minutes, not confidence).
- **Consequences:** `Rulebook.EffectiveAction` carries the winning override as `Entry` (WP14 PR A). `Rulebook.Site` has `Install-Hugo` and `Build-RulebookSite`; `New-RulebookPublishStage` writes the full `rulebook.json` and stages the catalog; `Publish.ps1` has a `-Phase Install` and a site step; the action has the input `hugoPath` and the failure kind `site`. The site files carry no ALCops URL and no branch name (the deploy rewrite does not reach `.js`, `.mjs`, `.css` and `.gotmpl`; a Deploy test checks it): the docs link and the issue URL come from `docsUrl` and `repository` of the data file. Known limit of the cart: after a `set` is widened to every level or stage, a more specific override that already decides a cell still wins there; the cart shows the chosen action, and the pull request of the apply workflow is authoritative.
- **Affects:** WP14 ([#16](https://github.com/ALCops/rulebook-engine/issues/16)), [#84](https://github.com/ALCops/rulebook-engine/issues/84), WP15 ([#17](https://github.com/ALCops/rulebook-engine/issues/17)).
