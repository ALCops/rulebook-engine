# D46. Seeded catalog ids are known; unadvertised, deprecated and vanished ids are catalog flags

- **Status:** Accepted
- **Date:** 2026-10-07

- **Decision:** the ids of the catalog seed the template ships are known ids that the scan never quarantines (the first scan only fills their package fields), and the three ways an id can be odd are recorded as flags on its catalog entry instead of states that change what the scan does: `advertised: false` for a descriptor no analyzer returns, `deprecated: true` for a deprecated descriptor, and an old `lastSeenVersion` for an id a newer package no longer carries.
- **Rationale:** the seed is the inventory the shipped levels were decided on, so every seeded id already has a place in the level files or sits at its analyzer default on purpose; quarantining 628 ids on the first scan would set every one of them to `None` and break the rulebook the organization just created. A descriptor no analyzer advertises (the ALCops `XX0000` analyzer exception ids, AS0141) can never be reported by the compiler, so quarantining it does nothing and would only clutter the quarantine files; it belongs in the catalog because the compiler accepts it in a ruleset and C7 must know it. Deprecated and vanished ids stay in the catalog so a level file that still names them keeps validating and the pull request can point them out; deleting them would turn every such mention into a C7 error after the first scan.
- **Rejected:** quarantining the seeded ids like any other new id (sets the whole shipped rulebook to `None`); dropping unadvertised ids from the catalog (C7 errors on ids the compiler accepts, and the pull request could not explain them); deleting vanished ids (C7 errors in level files that still mention them, and the history of when an id was last seen is lost); a `status` enum per entry (one field for three independent facts: an id can be deprecated and vanished at once, and an enum would need a precedence rule).
- **Consequences:** the catalog schema types `advertised`, `deprecated`, `firstStableVersion` and `defaultChanges`; the writer emits `advertised` only as `false` and `deprecated` only as `true`, so a seed entry and an ordinary scanned entry stay short. `Update-CatalogFromScan` reports seeded ids as `Recorded`, never as `NewIds`; unadvertised ids are cataloged and never quarantined; the pull request lists the three groups under Catalog notes, with the seeded ids no package carries. The template does not ship `catalog/scan-state.json`; the first scan creates it, and from then on C7 is an error. Contract: [reference/scan-mechanics.md](../reference/scan-mechanics.md) section 3.
- **Affects:** WP08 ([#10](https://github.com/ALCops/rulebook-engine/issues/10)), WP10 (the inventory refresh).
