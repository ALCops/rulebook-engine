# D27. Source files are deltas: level chain and stage deltas, flat sparse endpoints

- **Status:** Accepted
- **Date:** 2026-10-01
- **Note (2026-10-05):** for an id no file on the chain mentions, quarantine is part of the level result and wins over a stage entry; see [D41](0041-quarantine-wins-over-a-stage-entry-for-an-unmentioned-id.md).

- **Decision:** a level file `base/<slug>.ruleset.json` lists only the ids whose action differs from the level it is `basedOn`; a root level (no `basedOn`) lists only the ids whose action differs from the analyzer defaults. A stage other than `default` is one file `stages/<slug>.json` that lists the ids it changes, applied on top of every level's default-stage result, and only where the level result is defined and not `None` (S-1 to S-4 bind every stage, shipped or custom). The default stage has no file. The generator resolves per id: override, then twins setting, then stage delta, then level chain (walk from the root, last file that mentions the id wins), then quarantine (only for ids no file on the chain mentions), then analyzer default; it writes the id when the result differs from the catalog default (D22). Endpoints stay flat (D18) and sparse (D22). Entries in level and stage files carry `id`, `action` and `justification`.
- **Rationale:** nothing is repeated across levels or stages, and the generator computes the artifact as the deviation from the analyzer defaults, which is what the endpoint already is. This reinstates D6's idea at the source only; the include chain that made D6 expensive stays gone because the chain is folded in at generation time. One model serves the shipped four and every organization-added level or stage.
- **Rejected:** complete base files per level (D22; 13 files of 628 ids each, every placement repeated four to thirteen times); complete files for shipped levels and deltas for custom ones (two shapes to document and validate); one delta file per level per stage (a custom stage costs one file per level and the stage columns of the matrix are already level-independent tokens).
- **Consequences:** the shipped set is four level files (today 353, 352, 65 and 24 entries), two stage files (10 and 95 entries), `base/twins.json`, 12 endpoints and 12 skeletons. `base/` files are no longer the complete readable record; the matrix in `docs/rulebook/` is. The validation of an organization repository gains the chain resolution (C5: `basedOn` resolves, no cycle) and loses "every base file lists every catalog id". `Rulebook.Generate` gains `Resolve-LevelChain` and `Read-StageFile` (WP03). The engine's V13 composes the files and compares the result with `resolved.json`. Partly supersedes D19 (inputs and precedence), D22 (complete base files), D16 and D17 (generation wording); supersedes the `basedOn` half of D20.
- **Affects:** WP02, WP03, WP04, WP07, WP08, WP10, WP12; `docs/rulebook/composition.md` and `tools/rulebook/`.
